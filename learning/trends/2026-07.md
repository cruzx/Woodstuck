## 2026-07-02

- 主题：AI 设计助手正在从“会生成”转向“能复用团队评审口径”
- 外部信号：Figma 在 2026-07-01 进一步解释 Figma agent 的 skills 用法：团队可以把常用评审风格、UX writing 标准、可访问性检查、stakeholder 反馈方式、crit prep/recap、研究和数据引用等沉淀成可复用指令，并在 Figma agent / Figma Make / MCP connector 链路中调用
- 为什么值得在意：这说明 AI 设计工具的竞争点不只是单次出图质量，而是能不能把组织里的隐性判断、复盘格式、审稿流程和证据链变成可重复调用的工作流；对 `woodstuck` 这类判断型 skill 来说，这比“多看案例”更接近长期能力升级
- 对当前任务的可迁移点：后续做过稿、商业化评审或概念版收口时，可以继续把 `修改意见.md`、评审口径、角色视角、可访问性/文案/数据检查拆成独立可触发 skill 或 playbook；输出要能让别的工具、设计稿和项目管理系统继续承接，而不是只停在一段聊天建议
- 不能直接照抄的风险：不要把所有经验都塞进一个大 prompt；如果没有清晰触发条件、输入边界和验收格式，skills 只会变成新的长文档负担。适合沉淀的是反复发生的评审动作，不是一次性灵感
- 是否升级到 PROFILE：否，先观察；方向与 `woodstuck` 现有 thin-router / playbook 结构强相关，但还需要更多实际任务验证

## 2026-07-02

- 主题：音乐发现正在把“编辑推荐”从后台权威变成前台人格化内容
- 外部信号：Spotify 在 2026-06-12 把 editor-led video recommendations 放进美国区 New Music Friday，编辑会在播放列表里用短视频解释新歌、艺人和推荐理由；Spotify 同时提到 The Drop Weekly 自 2025-09 上线后带来更高的 save / like 参与
- 为什么值得在意：音乐推荐不再只是算法列表或编辑榜单，平台开始把“为什么推荐这首歌”做成可消费内容；这会增强新歌发现的信任感、故事性和艺人关系，也给商业化与会员运营提供更自然的解释层
- 对当前任务的可迁移点：以后做新歌发布、艺人专区、会员抢先听、概念版推荐或活动榜单时，可以给关键推荐加一层轻视频/短评/编辑理由：先让用户知道推荐背后的故事，再承接收藏、预约、分享、会员权益或艺人关注
- 不能直接照抄的风险：不要把每个推荐位都做成重视频讲解；只有在新歌、艺人、活动或榜单需要建立信任和话题时才值得加人格化解释。普通听歌场景仍要保持快进快听
- 是否升级到 PROFILE：否，先观察；这是音乐分发与内容解释机制的中期信号，先放月度趋势
- 来源：2026-06-12 Spotify For the Record《Meet the Curators: New Music Friday Gets a Personal Touch With Editor-Led Video》

## 2026-07-02

- 主题：短视频沉浸体验正在把“少打扰”和“更准反馈”拆成显式控制
- 外部信号：YouTube 在 2026-06-25 更新 Shorts 播放器，加入 Clear Screen mode 隐藏覆盖层、2x playback speed、轻量静音控制、timer 归零选项，并用 heart 替代 thumbs-up、下线 dislike，改用 Not Interested / Don't recommend this channel 作为更精确的负反馈
- 为什么值得在意：成熟内容流开始减少把所有互动按钮长期压在画面上的做法，同时把用户反馈从“喜欢/不喜欢”的粗粒度反应，拆成沉浸观看、效率消费、正向情感和明确不推荐几类信号；这能同时提升观看舒适度和推荐质量
- 对当前任务的可迁移点：以后做播放器、短视频、活动页或音乐内容流时，可以把主画面默认留给内容，把操作层做成可呼出/可退场；负反馈不要只做一个“叉掉/不喜欢”，要区分不感兴趣、减少同类、屏蔽来源、举报等不同语义
- 不能直接照抄的风险：不要为了“沉浸”把必要操作藏得太深；商业化点位、会员权益和活动入口如果必须被看见，应该跟随场景时机出现，而不是一直浮在内容上抢主任务
- 是否升级到 PROFILE：否，先观察；和播放器沉浸、推荐纠偏、干扰感控制相关，但需要更多音乐场景验证
- 来源：2026-06-25 YouTube Official Blog《How we're updating the YouTube Shorts experience》

- 为什么值得在意：专业创作者不缺一个新按钮，缺的是在原有产出链里更快试错、修正、复用和交付；AI 的价值开始从“生成一次很惊艳”转向“把编辑、变体、跨格式输出和团队协作成本降下来”

- 不能直接照抄的风险：不要把专业套件的复杂控制项直接搬到大众音乐产品；普通用户先要低门槛结果和明确下一步，深度编辑只能渐进展开

- 为什么值得在意：音乐产品的现场感不再只能靠演唱会售票或活动专题承接；平台可以把 `现场表演 / 官方视频 / 幕后片段 / Shorts 扩散 / 艺人频道沉淀` 串成一条持续内容链，既服务粉丝运营，也补足新歌和艺人曝光
- 对当前任务的可迁移点：以后做艺人活动、新歌发布、会员抢先看、概念版运营或播放器相关推荐时，可以把现场内容拆成三层：完整现场负责深度沉浸，短片段负责扩散，幕后/花絮负责粉丝关系和会员/预约承接
- 不能直接照抄的风险：不能把所有音乐运营都做成重视频现场；如果艺人、曲目或事件没有足够内容强度，硬做现场只会占用听歌主任务。更稳的是按内容热度和粉丝深度分层露出
